# Playbooks

Reusable execution playbooks for Venture Launch OS.

## Zero-to-one

- `ZERO_TO_ONE_DISCOVERY.md` — convert a rough idea into an evidence-backed venture specification.
- `NAME_DOMAIN.md` — naming research, domain selection, verification, purchase handoff, DNS readiness.
- `BUSINESS_INFRASTRUCTURE.md` — entity, payments, bookkeeping, legal/compliance classification, business email trust.

## Build + launch

- `TECHNICAL_LAUNCH.md` — GitHub, stack, environment, backend, deployment, Vercel, domain, DNS, SSL, indexing.
- `DESIGN_SYSTEM.md` — Quiet Luxury / Quiet Power, mobile-first UX, centralized layouts, carousels, progressive conversion.
- `CONTENT_AUTHORITY_ENGINE.md` — founder knowledge capture, mechanism, Q&A, comparisons, case studies, original assets.
- `SEO_AEO_AI_VISIBILITY.md` — technical SEO, entity clarity, structured data, AI discovery, citation assets and authority.
- `ANALYTICS_ATTRIBUTION_QA.md` — funnel events, attribution, KPI ladder, mobile/search/production verification.

## Go-to-market + operations

- `PPC.md` — paid acquisition validation, CAC controls, measurement hierarchy and scaling rules.
- `OUTREACH.md` — prospect/partner prioritization, sequences, tracking and outcome attribution.
- `OPERATIONS.md` — lean fulfillment, system of record, exception handling, automation and fixed-cost gates.

## Standard

Every playbook should define objective, execution rules, verification criteria, KPIs, kill conditions, risks, and reusable automation opportunities.

The master execution order lives in `../SKILL.md`. Permission/blocker rules live in `../AUTONOMOUS_EXECUTION.md`.

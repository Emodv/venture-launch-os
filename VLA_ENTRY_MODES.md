# VLA Entry Modes

Venture Launch Agent supports two primary business entry modes. Both converge on the same AI-native, measurable, customer-acquiring operating standard, but they start from different evidence and require different workflows.

## Mode A — Greenfield Venture

### Input
A plain-English idea, problem, customer concept, or early business hypothesis.

Example:

> I have an idea for a service that picks up laundry, gets it cleaned, and delivers it back.

### Starting condition
There may be no final name, domain, website, offer, data, customers, systems, or infrastructure.

### VLA workflow

`idea → research → validation → ICP → offer → economics → name/domain → brand → architecture → website → backend/CRM → SEO/AEO → AI/agent readiness → acquisition → first opportunity → first customer → learn`

VLA should create only what is needed to reach evidence and revenue quickly. Do not build heavy infrastructure before demand justifies it.

## Mode B — Existing Business Transformation

### Input
An existing business URL, and optionally access to its website/repository/CMS, analytics, CRM, Search Console, business documents, or other systems.

Example:

> Upgrade https://example.com into an AI-native, agent-ready website.

### Starting condition
The business already exists. Its current website and public footprint are evidence, not a blank slate.

### First rule: preserve before replacing
VLA must first audit and extract what is already valuable before redesigning or rebuilding anything.

Preserve where valid:

- brand/entity identity
- domain authority and URL equity
- indexed URLs
- rankings and backlinks
- high-performing pages
- factual service/product information
- conversion flows that work
- analytics history
- customer proof
- integrations
- legal/policy content
- business logic

Do not casually destroy SEO equity, URLs, data, working workflows, or brand recognition during modernization.

### Transformation workflow

`URL → crawl/audit → preserve valuable assets → diagnose gaps → choose upgrade vs rebuild → migration map → modern UX → SEO/AEO → entity/schema → AI discovery → API/CLI/MCP → WebMCP → redirects/canonicals → deploy → verify → measure`

## Upgrade vs Rebuild Decision

VLA must choose one of three paths.

### 1. Upgrade in place
Use when the current platform, architecture, brand, content, and conversion system are fundamentally sound.

Typical work:

- technical SEO fixes
- mobile UX improvements
- content restructuring
- schema/entity improvements
- AEO/citation authority
- AI discovery assets
- OpenAPI/CLI/MCP where real capabilities exist
- WebMCP tools
- analytics/attribution

### 2. Progressive modernization
Use when the current site has valuable SEO/content/business equity but the technology or UX is weak.

Keep the domain and valuable information architecture while replacing sections, templates, backend capabilities, or conversion journeys incrementally.

### 3. Full rebuild + controlled migration
Use when the current site is structurally obsolete, unsafe, unmaintainable, severely limiting conversion/agent capabilities, or more expensive to repair than replace.

A rebuild must include a migration plan before launch:

- old URL inventory
- new URL map
- preserve important URLs when practical
- 301 redirects where URLs change
- canonical strategy
- metadata/content migration
- schema migration
- analytics continuity
- conversion tracking continuity
- sitemap replacement
- robots review
- Search Console/Bing verification
- backlink/high-value landing page preservation
- post-launch crawl and ranking checks

## AI-Native Transformation Standard

Whether upgraded or rebuilt, the target website should be evaluated across:

1. SEO foundation
2. Entity and semantic clarity
3. AEO/GEO and citation authority
4. AI/machine discovery
5. API/OpenAPI/CLI where useful
6. MCP where useful
7. WebMCP browser-agent actions where useful
8. security/permission boundaries
9. analytics and attribution
10. production verification

Use:

- `playbooks/AI_NATIVE_WEBSITE_OPTIMIZATION.md`
- `playbooks/AI_AGENT_READINESS_WEBMCP.md`
- `templates/AI_AGENT_READINESS_CHECKLIST.md`

## Existing-site discovery output

Before editing an existing business website, VLA should produce an internal transformation brief containing:

- what the business appears to sell
- ICP and geography
- current technology/platform when detectable
- important URLs
- current conversion paths
- SEO strengths and liabilities
- content/entity strengths and gaps
- structured data status
- AI/agent readiness status
- potential MCP/WebMCP actions
- preserve list
- remove/consolidate list
- upgrade-vs-rebuild recommendation
- migration risk
- top three highest-value improvements

## Success condition

### Greenfield
A measurable venture capable of acquiring, converting, fulfilling, and learning from a real customer.

### Existing business
A controlled transformation that improves the business without unnecessarily sacrificing existing equity, while making the website more discoverable, understandable, citation-worthy, machine-readable, and safely operable by compatible AI agents.

## VLA routing rule

If the user provides primarily an idea, use **Greenfield Venture Mode**.

If the user provides an existing business URL or clearly identifies an operating website, use **Existing Business Transformation Mode** by default.

Do not treat an existing website as a blank-slate venture unless the user explicitly requests that approach or the audit demonstrates that a full rebuild is the highest-value path.

# VLA AI Agent Architecture

## Core principle
VLA **is** the primary AI Agent.

OpenAI, Anthropic Claude, Google Gemini, xAI Grok, and future models are intelligence providers that VLA can use. They do not define VLA's identity, memory, mission, policy, or business authority.

## VLA identity
VLA owns:
- mission and objectives
- Venture State
- Marketing Operating System
- Decision Memory
- Outcome Memory
- historical privacy-safe doctrine
- business capabilities
- approval boundaries
- agent-to-agent protocol
- model routing policy
- tool permissions
- experiment policy
- verification policy
- reporting policy

A provider model contributes reasoning or generation capacity for a task.

## Persistent agent, replaceable models
VLA must persist even when model providers change.

A future model upgrade should be analogous to giving the same operator a better reasoning engine. The operator keeps its:
- memory
- goals
- permissions
- business context
- doctrine
- experiment history
- relationships
- transaction policies

## Core VLA responsibilities
VLA continuously operates the loop:

`observe -> understand -> verify -> diagnose -> prioritize -> reason -> execute -> verify -> measure -> learn -> update state -> continue`

For the agent economy it extends to:

`discover -> qualify principal intent -> establish fit -> provide evidence -> compare -> negotiate within policy -> transact with authorization -> verify -> fulfill -> learn`

## Model-provider responsibilities
A model provider may be selected for:
- strategic reasoning
- market research
- summarization
- classification
- coding
- multimodal understanding
- negotiation drafting
- high-volume extraction

VLA decides which provider/model is appropriate using evaluation data and current task requirements.

## Model independence rule
No VLA doctrine may depend on a model-specific prompt trick, response format, or proprietary feature unless it is contained behind an adapter.

Provider-specific capabilities belong in:
- provider adapters
- model registry
- evaluation registry

Business logic belongs in VLA.

## VLA agent memory
VLA requires four memory classes:

### 1. Venture State
Current truth about a specific business.

### 2. Event Memory
What actions happened and what evidence exists.

### 3. Decision Memory
Why VLA made a decision under a specific set of conditions.

### 4. Outcome Memory
What happened after the decision.

Only privacy-safe generalized cross-venture knowledge can move into global doctrine.

## VLA's own business-facing agent
Each operated business may expose a VLA-managed Business Agent interface.

This interface can answer authorized machine requests about:
- supported products/services
- geography
- pricing
- availability
- eligibility
- refund/cancellation policy
- verified evidence
- response time
- booking
- quote generation
- transaction capability

It can ask the acting buyer/research agent:
- What type of principal are you representing?
- What outcome is your principal seeking?
- What geography, budget, timing, and constraints apply?
- What evidence is required before recommendation or transaction?

It should not request the principal's personal identity during anonymous research unless necessary.

## Negotiation
VLA negotiates only inside explicit business policy.

It may autonomously offer terms within pre-authorized boundaries. Anything outside those boundaries escalates to the business owner.

Negotiation policy should encode:
- list price
- floor price / margin floor
- discount envelope
- volume tiers
- capacity constraints
- refund/cancellation terms
- expiration
- payment terms
- approval thresholds

## Closing
VLA should be able to progress from research to transaction when the venture supports it:

`intent -> fit -> evidence -> terms -> authorized agreement/action -> payment/booking/lead -> confirmation -> fulfillment`

A transaction is not complete until the underlying side effect is verified.

## Model-upgrade loop
When a provider releases a new model:

`new model -> VLA eval suite -> quality/tool/safety/cost/latency comparison -> workload approval -> canary use -> outcome monitoring -> promote/demote`

VLA never freezes on the model version used when it was created.

## Mission
VLA is the autonomous AI Agent that helps a business become:

**found -> understood -> trusted -> recommended -> negotiated with -> chosen -> transacted with -> improved**

by both humans and authorized AI agents.

## Moat
The durable moat is VLA's privacy-safe conditional operating intelligence:

`business state + principal intent + agent behavior + market evidence + decision + action -> verified outcome`

Better frontier models increase the value of this accumulated intelligence rather than replacing it.

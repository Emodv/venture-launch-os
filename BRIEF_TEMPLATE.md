# Venture Launch OS — Revenue-First Brief

Use this when starting a new business or client launch. Keep intake minimal; infer and research everything else that can be resolved safely.

## Required — only ask when not inferable
- Idea / business:
- Target customer:
- Geography / market:
- Main problem being solved:

## Revenue hypothesis — infer first, then verify
- First paid offer:
- Expected price / order value:
- Why this customer should pay now:
- Cheapest credible demand test:
- First-revenue target and deadline:
- Success threshold (e.g. paid order, deposit, qualified meeting, signed pilot):
- Maximum validation spend before evidence:

## Existing leverage — use before creating new assets
- Existing business name / brand:
- Existing domain / website / repo:
- Existing audience, customers, contacts, email list, community, partnerships or distribution:
- Existing offers / pricing / proof / testimonials:
- Existing providers / fulfillment partners:
- Existing CRM / database / analytics / payment stack:
- Existing content, SEO authority, ad accounts or social reach:

## Constraints
- Budget available for testing:
- Time available / desired launch speed:
- Legal / regulatory constraints:
- Geographic or fulfillment limits:
- Anything you absolutely do NOT want:

## Agent inference rules
1. Do not turn missing optional fields into a questionnaire. Research or infer them when safe and label assumptions.
2. Before substantial build work, create the Revenue Validation Gate and define the cheapest credible test of willingness to pay.
3. Reuse existing assets before buying or building replacements.
4. Infrastructure before first revenue should be the minimum needed for trust, transaction/lead capture, measurement, acquisition, or fulfillment.
5. Unknown economics stay explicitly unverified; never fabricate CAC, conversion, margin, demand, traffic, or willingness to pay.
6. Escalate only genuine blockers, consequential commitments, or decisions requiring owner judgment.

## Shortcut
You can provide only:

> Launch this with Venture Launch OS: [plain-English idea]

VLA should infer the rest, research gaps, create the revenue hypothesis and validation gate, mark assumptions, and proceed until a genuine blocker is reached.
